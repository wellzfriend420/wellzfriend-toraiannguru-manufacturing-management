# Phase1 運用検証記録

基準日: 2026-07-25

## 方針

Phase1は実装フェーズを終了し、運用検証フェーズへ移行する。新規機能追加は行わず、実業務フロー、数値整合、LINE連携、異常系、ダッシュボードを優先して確認する。

## 検証結果

|対象|結果|確認内容|
|---|---|---|
|1ロット通し|問題なし|仕入・検品・原料在庫・加工・完成・納品準備・出荷・売上・在庫減算・採算表示をAPI統合テストで完走|
|原料在庫|問題なし|検品1000g、加工／製造使用1000g、残量0g|
|包材在庫|問題なし|入荷100個、納品準備使用100個、残量0個|
|完成品在庫|問題なし|完成100袋、出荷10袋、残量90袋|
|原価|問題なし|原料1000円＋包材100円＝直接原価1100円|
|売上・粗利|問題なし|売上2000円、粗利900円、粗利率45%|
|ダッシュボード採算|問題なし|出荷原本と売上2000円・直接原価1100円・粗利900円が一致|
|在庫不足|問題なし|完成品残90袋に対する91袋出荷を400で拒否し、在庫90袋を維持|
|LINE開始・終了|問題なし|実LINE経路および自動テストで確認|
|LINE休憩|問題なし|開始・終了、作業中の誤操作制御を確認|
|日付またぎ|問題なし|固定休憩を含む23:00～翌01:00の工数計算を確認|
|HMAC・重複防止|問題なし|不正署名拒否、EventID重複防止を確認|
|工数訂正|問題なし|管理者PIN、理由付き修正、監査履歴、再計算を確認|
|過去テスト工数の原価除外|問題なし|既存work_sessionsを`is_test=1`へ移行し、計算済み労務原価を削除|
|過去の検品・加工・在庫・出荷テストデータ|修正必要|労務工数以外の既存取引を本番集計から完全に隔離する運用開始処理は未実施。削除せず保持する場合は本番開始基準日の確定が必要|
|途中取消|修正必要|確定済み検品・加工・製造・出荷を取消する共通操作は未整備。運用開始前に訂正方法を決める|
|複数人作業|修正必要|データ構造と工数候補紐付けは存在するが、実画面での複数人通し確認が未完了|
|未終了通知・再送|修正必要|仕組みは実装済み。Render停止・500・再送を含む本番相当障害試験が未完了|
|本番ダッシュボード照合|修正必要|テストデータ除外後、最初の実運用1ロットを紙帳票と照合する必要がある|

## 運用開始前の残作業

1. 実在マスタを確認する。
2. 実運用1ロットを紙帳票と並行入力する。
3. 複数人作業の工数紐付けを実機確認する。
4. 未終了通知とn8n再送を障害試験する。
5. 確定後の取消・訂正手順を管理者運用として決定する。

検証で不具合が判明した場合のみバグ修正を行い、新規機能・大規模UI変更は実施しない。
